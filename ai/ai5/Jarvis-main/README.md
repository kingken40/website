# J.A.R.V.I.S.

### Just A Rather Very Intelligent System

For decades, we watched Tony Stark talk to an AI that felt really alive. Helpful, witty, and always there when needed. It was connected to all his systems, carried out tasks for him, and helped him build projects.

Most of us assumed it would just stay in the movies forever.

I decided not to wait.

I built a fully local, high-performance, and deeply integrated always-on voice assistant that aims to fully recreate the feel of Jarvis. It also actually sounds like him, using a voice clone of Paul Bettany, the original voice actor, with all audio routed through SoX to achieve the iconic movie-accurate robotic intercom filter.

Built around a low-latency pipeline: [Picovoice Porcupine](https://picovoice.ai/docs/porcupine/) wake-word → [Whisper](https://github.com/openai/whisper) STT → [Grok](https://x.ai/) / [Groq](https://groq.com/) LLM → [OpenClaw](https://github.com/OpenClaw) → [Qwen TTS](https://github.com/QwenLM/Qwen3-TTS) → [SoX](https://sox.sourceforge.net/) audio processing

---

## How It Works

**Wake word → listening**

The script runs continuously in the background, polling the microphone frame by frame through [Picovoice Porcupine](https://picovoice.ai/docs/porcupine/): a lightweight on-device wake-word detector that uses negligible CPU while idle. When it hears "Jarvis", it immediately responds with "Sir" or "Yes, sir", switches the RGB lighting, and opens a recording session. The audio is captured until you stop speaking, then passed to [Whisper](https://github.com/openai/whisper) for transcription.

**LLM response**

The transcribed command is sent to the LLM with the full conversation history and a long-term memory file loaded into the system prompt on every turn. The LLM handles everything it can directly: conversation, reasoning, quick answers, and simple local commands via one-shot shell tags. Responses start generating immediately and are streamed to the TTS engine as they arrive, so Jarvis begins speaking before the full response is even finished.

If the LLM determines a task needs real tool use, it responds with a short spoken acknowledgement and includes a routing tag in its output. The script intercepts this tag and simultaneously dispatches the request to OpenClaw while the acknowledgement is still being spoken.

**OpenClaw (parallel tool use)**

[OpenClaw](https://github.com/OpenClaw) is a separate AI agent with access to real tools:  file operations, web search, calendar, system control, and more. It receives the user's request along with the recent conversation context and runs in parallel with the LLM's spoken response. Its reply is queued and plays back immediately after the LLM finishes speaking, delivered through the same voice and audio chain. From the user's perspective it sounds like one continuous Jarvis response.

**Audio pipeline**

All speech is generated by [Qwen TTS](https://github.com/QwenLM/Qwen3-TTS) running locally on your GPU, using a voice clone built from Paul Bettany's original recordings. Audio chunks are streamed in real time into [SoX](https://sox.sourceforge.net/), which applies the equalizer, chorus, overdrive, and gain chain that produces the characteristic Jarvis intercom sound. A single serial audio worker thread ensures nothing ever plays simultaneously; Grok and OpenClaw responses always queue cleanly one after the other.

**Follow-up turns**

After Jarvis finishes speaking, the script stays open for a configurable number of seconds listening for a follow-up without requiring the wake word again. If you keep talking, the conversation continues naturally. If you go silent, it returns to standby and waits for "Jarvis" again.

## LLM

The LLM is Jarvis's brain. It's responsible for personality, reasoning, conversation, and deciding what to handle directly versus route to OpenClaw. Two engines are supported, selectable via `LLM_ENGINE` in the config.

### Grok (recommended)

[Grok](https://x.ai/) is the default and recommended engine. The model used is [`grok-4-1-fast-non-reasoning`](https://docs.x.ai/models/grok-4-1-fast-non-reasoning), chosen specifically for its low time-to-first-token (TTFT), which matters significantly in a voice assistant context where every extra second of silence breaks immersion. It is a paid API with no free tier, but costs are low: $5 worth of credits should easily last you a couple months to a year, depending on usage. The system prompt uses [prompt caching](https://docs.x.ai/developers/models#cached-prompt-tokens) to avoid re-billing the full context on every turn, which keeps costs down considerably during long sessions.

### Groq (free alternative)

[Groq](https://groq.com/) (different company, similar name) runs open-weight models on custom inference hardware specifically designed for low-latency generation. The free tier includes 14,400 requests per day on most models, which is more than enough for personal use. The default model is `llama-3.3-70b-versatile`. It is genuinely capable and fast, though you may notice a difference in the quality and nuance of Jarvis's personality compared to Grok. `gemma2-9b-it` is also available as a lighter, faster option if latency is your priority.

Note that prompt caching is a Grok-specific feature and is automatically disabled when using Groq.

## Requirements

### System

- Linux, macOS, or Windows
- Python 3.11+
- A CUDA-capable GPU (required for Qwen TTS)
- [SoX](https://sox.sourceforge.net/) with MP3 support — install via your package manager:

```bash
# Linux
sudo apt install sox libsox-fmt-mp3
# macOSbrew 
install sox
# Windows
choco install sox
```

- [OpenRGB](https://openrgb.org/) running with SDK server enabled _(optional, for RGB lighting effects)_

```bash
pip install pvporcupine pvrecorder openai-whisper numpy torch openai openrgb-python flash-attn
```

## Setup

### 1. Clone the repo

```bash
git clone https://github.com/TheWoomy27/Jarvis.git
cd Jarvis
```

### 2. Set your API keys

Open `jarvis.py` and fill in the config section near the top. At minimum you need a Picovoice key and one LLM key:

```python
# Wake-word
ACCESS_KEY = "your-picovoice-key"

# LLM — fill in whichever engine you are using
XAI_API_KEY  = "your-xai-key"    # Grok (recommended)
GROQ_API_KEY = "your-groq-key"   # Groq (free alternative)

# Then set the engine toggle
LLM_ENGINE = "grok"  # or "groq"
```

### 3. Add your wake-word model

Download a `"Jarvis"` wake-word model for your platform from the [Picovoice Console](https://console.picovoice.ai/ppn) and place the `.ppn` file in the project root. Update the path to match:

```python
KEYWORD_PATH = "Jarvis_en_linux_v4_0_0.ppn"    # Linux
# KEYWORD_PATH = "Jarvis_en_mac_v4_0_0.ppn"    # macOS
# KEYWORD_PATH = "Jarvis_en_windows_v4_0_0.ppn" # Windows
```

### 4. Set up your audio folder

The script expects a set of `.wav` sound effects and voice lines for feedback. Copy the `Audio` folder to the project root (or adjust the paths in the script).

Each folder inside can contain multiple `.wav` files — some are picked at random each time for variation.

### 5. Set up Qwen voice cloning

Place a clean reference audio clip of Paul Bettany speaking (WAV, ideally 10–30 seconds, no background noise) in the project and update:

```python
REFERENCE_AUDIO = "Audio/Jarvis Reference.wav"
REFERENCE_TEXT  = "The exact transcript of what is spoken in that clip."
```

### 6. Run

```bash
python jarvis.py
```

The first run will take noticeably longer than usual as models are downloaded and `torch.compile` builds and caches the Qwen TTS computation graphs. Subsequent starts are fast.

## Voice Clone

Results of the voice clone depend heavily on what Paul says and how he says it. I found that the best way to get good reference audio is to use the voice lines from the now discontinued [JARVIS: A Second Screen Experience](https://ironman.fandom.com/wiki/Marvel's_Iron_Man_3_-_JARVIS:_A_Second_Screen_Experience) iOS app, which is the only source I could find for isolated audio recordings of Paul Bettany's voice. I obtained them through [this Reddit post](https://www.reddit.com/r/Marvel/comments/71k7nk/iron_man_3_jarvis_app_sound_files/) and have also included all 380 of the extracted files converted from `.caf` to `.wav` in `Audio/JARVIS: A Second Screen Experience`. They are also available from [this YouTube video](https://youtu.be/9hhIc8iWUx4?si=ul7HH6Md-W1nxzhr).

Qwen TTS works best with 10–30 seconds of audio, so we can't use all of the original recordings and need to selectively choose which phrases are included in the reference audio. I've done a bit of experimenting with different combinations and am satisfied with the reference audio included in this repo. Feel free to test your own combinations, as they may end up sounding better. If you change the reference audio, make sure to also update the `REFERENCE_TEXT` variable to match.

### Cloud TTS alternatives

If you don't want to run Qwen locally, two cloud alternatives are supported. To use either, set `TTS_ENGINE` to the appropriate value and uncomment the corresponding client, config variables, and audio generation block in `_speech_worker()`.


**[ElevenLabs](https://elevenlabs.io/) — free tier available**

ElevenLabs has a free tier and is the easiest way to get started without a GPU. However, it will not sound like Jarvis; there is no Paul Bettany voice available on the platform. The default `VOICE_ID` in the config is the closest match I could find to the Jarvis character, but it is just a generic British voice, and you can replace it with a different one if you'd like. If you have your own (paid) ElevenLabs voice clone, swap in its ID. Set `TTS_ENGINE = "eleven"`, add your key, and install the package:

```python
ELEVEN_API_KEY = "your-elevenlabs-key"
VOICE_ID       = "jRAAK67SEFE9m7ci5DhD"  # replace with your own if preferred
```

```bash
pip install elevenlabs
```


**[Fish Audio](https://fish.audio/) — paid, sounds like Jarvis**

Fish Audio supports voice cloning from a reference model ID, and with a good [Jarvis model](https://fish.audio/m/612b878b113047d9a770c069c8b4fdfe/) it produces results comparable to Qwen. This is the best cloud option if you want the authentic voice without running a local model. It is a paid service with no meaningful free tier. Set `TTS_ENGINE = "fish"` , add your key, and install the package:

```python
FISH_API_KEY  = "your-fish-api-key"
FISH_MODEL_ID = "612b878b113047d9a770c069c8b4fdfe"
```


## Configuration

All tunable values are at the top of `jarvis.py`:

| Variable            | Default                     | Description                                                                         |
| ------------------- | --------------------------- | ----------------------------------------------------------------------------------- |
| `LLM_ENGINE`        | `"grok"`                    | Which LLM backend to use: `"grok"` or `"groq"`                                      |
| `GROQ_MODEL`        | `"llama-3.3-70b-versatile"` | Groq model to use. `"gemma2-9b-it"` is faster but less capable                      |
| `TTS_ENGINE`        | `"qwen"`                    | Which TTS backend to use: `"qwen"`, `"eleven"`, or `"fish"`                         |
| `ALWAYS_FOLLOW_UP`  | `True`                      | If `True`, Jarvis keeps listening after each response for a follow-up               |
| `LINGER_SECONDS`    | `2.5`                       | Seconds to hold the active RGB effect after Jarvis finishes speaking                |
| `SILENCE_THRESHOLD` | `700`                       | RMS value below which audio is treated as silence; raise this if your room is noisy |
| `SILENCE_SECONDS`   | `1.5`                       | How long silence must persist before recording cuts off                             |
| `MAX_COMMAND_TIME`  | `60`                        | Hard cap on recording length in seconds                                             |
| `FOLLOW_UP_TIMEOUT` | `4.0`                       | Seconds to wait for a follow-up before returning to standby                         |
| `RGB_ENABLED`       | `False`                     | If `True`, enables RGB lighting effects on startup, conversation, and shutdown      |

## Memory

Jarvis loads a `memory.md` file at the start of every conversation. This is his long-term memory across sessions; it stores info about you, your preferences, project context, and facts about your setup. It is plain markdown and you can edit it directly with whatever you feel Jarvis should know to be more useful.

Ideally, this should be similar to your OpenClaw `MEMORY.md`.

## OpenClaw Integration

[OpenClaw](https://github.com/OpenClaw) is the external agent Jarvis routes to for tasks requiring real tool use. It runs as a subprocess and receives the user's request along with the recent conversation context so it can pick up seamlessly where the LLM left off. The two agents coordinate through the system prompt; the LLM knows it is the first half of a single Jarvis response, and OpenClaw delivers the result.

## OpenRGB Integration

This project supports [OpenRGB](https://github.com/CalcProgrammer1/OpenRGB) lighting effects that activate while Jarvis is engaged and return to your default idle effect when the conversation ends. Startup and shutdown also have their own effects.

These effects are turned off by default.

To use them, set `RGB_ENABLED = True`, make sure the [Effects plugin](https://openrgb.org/plugin_effects.html) is loaded in OpenRGB, and start the SDK server. The script will find it automatically and expects your list of effects to look like this:

```
 0 | Shaders
 1 | Layers
     2 | Shaders
     3 | Breathing
     4 | Gradient Wave
 5 | Crossing Beams
 6 | Bubbles
 7 | Breathing Circle
 8 | Mosaic
 9 | Fill
```

This is my personal RGB configuration; yours will differ. `"Shaders"` is my idle effect, active both on standby and when the script isn't running. `"Layers"` is a combination of a solid dark background, a slow breathing animation, and an audio visualizer that reacts to Jarvis's voice using the dark teal and cyan color scheme from the iOS app. The remaining effects are used during startup and shutdown.

Modify the effect names throughout the script to match your own OpenRGB setup, or recreate mine using the Effects plugin. I've included my effect profile in the repo. Place it in: `OpenRGB/plugins/settings/effect-profiles/`

I recommend pairing it with the [Visual Map Plugin](https://openrgb.org/plugin_visual_map.html). You will need to register a controller for each effect unless you configure the effects to target your devices directly.

> **Warning:** Do not enable multiple effects simultaneously. This will cause your devices to flicker and may overload them.

Getting the RGB working is time-consuming to tailor to your specific setup, which is why it is off by default, but it does add a lot to the experience and is worth the effort. Feel free to reach out if you run into issues; there are a lot of quirks.

## FAQ

### Which LLM should I use?

**Grok** is the recommended default, as it has the fastest time-to-first-token (TTFT) for a voice assistant use case and the quality is excellent. **Groq** is a solid free alternative running Llama 3.3 70B on specialized inference hardware with sub-500ms TTFT. Response quality is slightly lower than Grok for nuanced personality, but it works well and the free tier is generous.

### Why not just use OpenClaw for every turn?

Because OpenClaw is slow and expensive. Every turn would take 5–10 seconds to respond, breaking the immersion entirely. Routing to the LLM first gives you a response almost instantly, and it only follows up with OpenClaw when tool use is genuinely needed. The script also uses prompt caching when using Grok, which lowers cost and increases speed further.

### Why does the first response after startup take longer?

The script sends a silent warmup request to the LLM at startup to pre-load the system prompt into the API's cache. If the warmup hasn't finished by the time you speak your first command, that request pays the full cold-start cost. This typically only happens if you trigger the wake word within the first few seconds of the script being ready. Wait for the startup sound sequence to fully complete before speaking.

### Why is Qwen TTS slow on the first run?

`torch.compile` needs to build and cache computation graphs the first time it runs. This is a one-time cost per machine; subsequent startups skip it and load from cache. If you're seeing slow generation on every startup, check that `TORCH_COMPILE_CACHE_DIR` is pointing to a writable directory.

### Jarvis is mishearing me or picking up background noise. What should I tune?

Raise `SILENCE_THRESHOLD` in the config. The default of `700` is calibrated for a quiet room. If you have a fan, AC, or ambient noise, bump it to `1000`–`1500`. If Jarvis is cutting you off mid-sentence, lower `SILENCE_SECONDS` slightly or raise the threshold so it doesn't mistake a breath for silence.

### Jarvis keeps responding to things I didn't say. What's happening?

This is Whisper hallucinating, which is a known quirk where the model generates plausible-sounding text when the audio is just silence, background noise, or something too quiet to transcribe accurately. The script has two defenses against this: it checks Whisper's own `no_speech_prob` score and discards anything above 0.6, and it filters a hardcoded list of common hallucinations like "Thank you." and "Okay." that Whisper frequently produces from silence.

If you're still seeing false triggers, there are a few things to try. Raise `SILENCE_THRESHOLD` so the script is less likely to start a recording session from ambient noise in the first place. You can also add your own recurring false positives to `HALLUCINATION_LIST` in the config; just add the exact string Whisper keeps producing and it will be silently discarded going forward.
### Can I use a different wake word?

Yes. Train a custom keyword model on the [Picovoice Console](https://console.picovoice.ai/ppn) and point `KEYWORD_PATH` at the new `.ppn` file. The rest of the script is wake-word agnostic. Keep in mind the `.ppn` file is platform-specific and you will need a separate one for Linux, macOS, and Windows.

### OpenClaw isn't responding or the gateway isn't connecting. What do I check?

Make sure the OpenClaw gateway is running before starting the script. Jarvis launches the agent as a subprocess and expects it to be available. Check that `openclaw` is on your `$PATH` by running `openclaw --help` in a terminal. If the gateway crashes mid-session, Jarvis will let you know and fall back gracefully without crashing.

### Does this work without a GPU?

Qwen TTS requires CUDA. Without a GPU, you can still run the script by switching `TTS_ENGINE` to `"eleven"` or `"fish"`, both of which are cloud-based and have no local compute requirement. Whisper will fall back to CPU automatically but will be significantly slower; consider using `whisper.load_model("small.en")` instead of `"turbo"` if you are running on CPU only.

### Can I run this without OpenClaw?

Yes. If you don't have OpenClaw set up, the script runs fine, Jarvis just won't be able to execute tool-use tasks. The LLM will still handle all conversational responses, reasoning, and one-shot shell commands via the `<action>` tag. You'll want to remove or adjust the routing instructions in `SYSTEM_PROMPT` so the LLM doesn't try to route to a tool it can't reach.

### Is there or will there be a GUI in the future?

Not right now. Eventually maybe, but a terminal output is fine for now. Running it alongside [cava](https://github.com/karlstav/cava) looks great.
